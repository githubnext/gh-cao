CAO [v0.2.0](https://github.com/githubnext/gh-cao/releases/tag/v0.2.0) is a pre-release. The comparison from v0.1.28 contains 97 commits; I inspected the commit list and verified each behavior below against the repository files at the release tag. Many commits are documentation refreshes, debug-logging extractions, and CI changes, and I left those out.

## Use `gh cao` for setup and lifecycle commands

The Node onboarding and lifecycle commands are retired. According to `ARCHITECTURE.md` at the tag, `init`, `setup`, `setup-auth`, campaign `add`, `mode`, `enable`, `disable`, `update`, and `upgrade-gh-aw` now fail with guidance that points to the native replacement. `gh cao` owns the operator interface, and the Node `cao` entry point keeps the Actions runtime and the evidence APIs that agents use inside workflows ([#19565](https://github.com/githubnext/gh-cao/pull/19565)).

The root `README.md` now starts with `gh extension install githubnext/gh-cao` followed by `gh cao setup`. It says native setup prepares missing gh-aw, runtime files, and baseline policy without installing Node.js. If GitHub CLI can't download the extension because of SAML authorization, the README keeps the curl installer as a fallback, which still requires Node.js 24 or later ([#19565](https://github.com/githubnext/gh-cao/pull/19565), [#19533](https://github.com/githubnext/gh-cao/pull/19533)).

## Run a local dashboard on a read-only snapshot

The local Go server now keeps the downloaded SQLite snapshot read-only and attaches a separate writable overlay to it. By default the overlay sits next to the snapshot with a `.local.sqlite` suffix; `--sqlite-overlay PATH` chooses another file ([#19684](https://github.com/githubnext/gh-cao/pull/19684)).

Per `server/README.md`:

- Local backfill starts in the background and repeats five minutes after each pass. It reads `GH_TOKEN`, then `GITHUB_TOKEN`, then `gh auth token`.
- It refreshes only repositories already declared in the snapshot, up to 10,000, within a bounded 30-day window. The README describes this as recent-evidence refresh, not a complete historical archive.
- The token goes only to the collection subprocess, not to SQLite or the browser.
- `--backfill=false` serves offline. An overlay is bound to its snapshot's content revision, so choose a new overlay file after replacing the snapshot. A mismatched overlay fails closed.

## Repair mixed-repository Activity shards

Activity compaction now tries to repair shards that mix repositories. It splits records with unambiguous repository identities into the declared repository groups and reports the count as `repairedShards`. Contradictory identities, unattributable records, and shards with undeclared repositories still fail closed, and the original shards are removed only after every output is written ([#19730](https://github.com/githubnext/gh-cao/pull/19730), documented in `activity/README.md`).

## Keep the repository list current

When you run the hosted server, signed repository creation, unarchive, rename, transfer, archive, and deletion events now queue reconciliation hints. Workers also refresh the App's installation list on startup and hourly. You can force a repair with `cao-dashboard backfill --repositories-only`, and `CAO_COLLECT_REPOSITORY_REFRESH_INTERVAL` overrides the default `1h` cadence ([#19701](https://github.com/githubnext/gh-cao/pull/19701)).

## Dashboard cost estimates are labelled

The Overview now has a "Cost estimates" section stating that all costs are estimates and pointing you to your billing dashboard for precise numbers ([#19547](https://github.com/githubnext/gh-cao/pull/19547)).

## Optional session archive

[#19746](https://github.com/githubnext/gh-cao/pull/19746) adds a default-off private Parquet session archive with DuckDB and optional ADX queries. `server/SESSION-ARCHIVE.md` says its ADR remains proposed until deployment acceptance gates have evidence. I haven't verified it in a running deployment, so treat it as experimental.

## What I left out

I did not describe the other docs, glossary, dependency, CI, and logging commits. I could not confirm from file contents alone how any of these changes behave in your deployment.

## What to do next

Read the [v0.2.0 release page](https://github.com/githubnext/gh-cao/releases/tag/v0.2.0). Because this is a pre-release, try it in a non-production control repository first. If you scripted Node `setup`, `init`, or campaign `add`, move to `gh cao` equivalents before upgrading, and upgrade the extension with `gh extension upgrade gh-cao`.
