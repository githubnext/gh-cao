# CAO Campaign and Workflow Marketplace

The marketplace is a read-only catalog projection. It does not install packages
or grant control-plane authority.

## Registry configuration

`control-plane.marketplace.registries` is an ordered list. Earlier registries
have higher precedence when two registries expose the same package coordinate.
CAO-created policies include the official CAO catalog and the Agentics workflow
collection explicitly; deleting either entry removes it.

Each registry declares `id`, `repository`, optional `path`, and `ref`. Optional
`format` is `packages` (the default) or `workflows`. Package registries discover
nested `aw.yml` manifests. Workflow registries discover only direct `.md`
children of `path`, excluding README files and nested shared fragments. The
Agentics registry uses repository `githubnext/agentics` and path `workflows`.
Markdown without frontmatter and a top-level `on` trigger, or with
`private: true` frontmatter, is not an installable workflow entry.

Optional `api-url` scopes a registry to a GitHub Enterprise API endpoint. Authentication
is `none`, `pat`, or `github-app`. Authenticated entries contain only environment
secret names:

- `pat`: `secret`
- `github-app`: `app-id-secret`, `private-key-secret`, and
  `installation-id-secret`

Resolvers read those named secrets only in the trusted Activity or hosted
backend. Secret values and access tokens are never serialized.

Removing a registry changes only discovery and display, never execution
permissions.

Local Go/PostgreSQL serving uses the same runtime registry source as hosted
serving. An empty or populated snapshot collection MUST NOT shadow that
registered source when a runtime provider is configured. Without a runtime
provider, snapshot-only readers continue to read retained package inventory.
Registry resolution remains read-only and MUST NOT write to canonical
snapshot.

## Package contract

Both backends return rows with the same safe fields:

`id`, `registry-id`, `registry-name`, `registry-precedence`, `name`,
`description`, `publisher`, `repository`, `repository-link`, `path`, `ref`, `resolved-commit`,
`version`, `icon`, `artwork`, `contents`, `readme`, `readme-path`, `source`,
`add-command`, `stars`, and `forks`.

`stars` and `forks` are nonnegative counts only when the GitHub repository API
confirms a public repository and provides both values. Both are `null` for
private, inaccessible, or incomplete repository data. The read-only static
Activity projection and hosted resolver expose the same safe fields.

`repository-link` is a safe repository relation link derived from the registry's
GitHub API URL when its public repository URL can be determined. It is omitted
for unsupported API URL shapes.

The package `id` identifies the case-insensitive repository/path coordinate and
does not change when a mutable registry ref resolves to a new commit. `source`
and `add-command` retain the resolved commit, so the package identity stays
stable while the reviewed install coordinate remains immutable.

Metadata is read from each package's gh-aw `aw.yml`. `readme` carries the
Markdown published in the `README.md` beside that manifest, bounded to the
same size limit as the manifest itself; a missing, oversized, or unreadable
README resolves to empty content and never fails its registry. The command is generated by
the resolver from normalized package coordinates as
`gh cao add REPOSITORY[/PATH]@RESOLVED_COMMIT`.

Workflow entries use the same row contract without adding canonical entity
fields. Their path includes the Markdown filename, `contents` contains that
workflow path, and the command is `gh aw add REPOSITORY/PATH.md@RESOLVED_COMMIT`.
Names come from frontmatter `name`, then the first level-one body heading,
then the filename without `.md`. Descriptions come from frontmatter, including
literal and folded multiline descriptions. The detail preview uses the matching
`docs/FILENAME.md` when available, otherwise the workflow body. A missing or
unreadable documentation blob does not make a workflow unavailable.

Both resolvers normalize gh-aw's colon-wrapped Octicon metadata (for example,
`icon: ":shield:"`) to the bare name (`shield`) used by the dashboard renderer.
Already bare names and other icon values are preserved; an omitted or empty
icon defaults to `workflow`.

Registry failures are isolated and reported as credential-free diagnostics.
The Go resolver defaults ordinary GitHub JSON responses to a 512 KiB bound before
decoding, reading at most one additional byte to detect overflow. This budget
allows base64-wrapped package blobs; manifest and README content limits remain
256 KiB. Only recursive repository-tree discovery has a larger, separate 8 MiB
ceiling to accommodate paths across the entire registry repository. Artwork
fields are references, not image downloads through the JSON reader.
The centralized defaults in `server/internal/inputlimits/limits.go` can be
overridden with `CAO_MARKETPLACE_JSON_MAX_BYTES` and
`CAO_MARKETPLACE_TREE_JSON_MAX_BYTES`. Values must be positive decimal byte
counts below the platform integer maximum, reserving one byte for overflow
detection. An unset override uses its default; an invalid or empty override
fails before the corresponding HTTP request, without silently falling back.
Oversized, unreadable or malformed responses fail the affected registry, except
optional README/documentation failures, which retain their logged empty-content
behavior. JSON responses must contain a single complete document; trailing
whitespace counts toward the byte
limit, and trailing documents or garbage are rejected. Request cancellation
is preserved. Repository-signal responses retain their separate 64 KiB bound.
Repository lookup failures do not hide usable packages. Private repository
counts and token-derived details are never published, even to authenticated
dashboard clients. The marketplace displays the package table as a declarative
card list without search, filters, or derived rankings. The directory loads
canonical query pages of 25 packages as the user scrolls, with an accessible
manual load/retry control. Summary cards show the package name, description,
publisher, and registry; version and public repository statistics remain on
the detail page. Mobile introductory text has a 16-pixel horizontal gutter.
