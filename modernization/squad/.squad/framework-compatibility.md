# Native Squad runtime boundary

## Exact supported invocation

Native Copilot `--agent squad --disable-builtin-mcps`, with the complete committed
bundle materialized in its workspace and an actual CAO admission envelope.
No Squad CLI, SDK, MCP state bridge, launcher or package installation is needed.
The host must provide real native specialist delegation, bounded file access
and any commands actually admitted for the phase. Missing tools block the
affected task; there is no mock runner or inline specialist impersonation.

The upstream **Squad 2.0.0-preview.4** prompt is explicitly adapted, not claimed
byte-identical or fully framework-compatible. Its name, native front matter,
upstream version, both original canaries, accountable-owner/delegation concepts
and strict reviewer lockout are retained. The fixed actual roster/cast and
specialist expertise are preserved. The stale generated zero-member bootstrap,
CLI/MCP bootstrap and unsupported automatic lifecycle branches were removed.

Seven pinned framework references and three pinned satellite skills are bundled.
Enabled prompt paths load these as ordinary local documents; host skill
registration is optional. Spawn/completion/model/state references are explicitly
adapted to the actual local capability surface, not presented as untouched
runtime algorithms. All original/final hashes and relocated skill source paths
are recorded in `../squad-source.json` relative to the bundle root.

## Casting integrity

The four casting JSON files remain byte-for-byte unchanged. Their shared
transaction/revision and registry/history commit-marker hashes are coherent.
Identity-assignment history is required provenance, not engagement history.
Workers read but never recast, migrate or mutate this registry.

## State and deliberate limitations

Read [native gh-aw local state](native-gh-aw.md) for the canonical capability
contract. Config explicitly selects `native-gh-aw` and `local`; nonlocal
backends, external team roots and upstream inheritance are rejected.

Ordinary files have no distributed locks, atomic CAS/create-if-absent service or
transactional multi-file guarantee. Shared writes require one serialized owner
and exact admitted paths, with before/after inspection. Unexpected competing
changes or uncertain writes block persistence. Optional missing write permission
is `not persisted`, never a missing MCP service or a fabricated durable record.
Required acceptance evidence must still be retained through a declared workflow
mechanism or its gate remains blocked.

No imported histories, identity wisdom, prior decisions/audits, customer evidence
or learned memory are required for startup. No automatic history/log generation,
archival, monitoring, upstream fetching, init, upgrade, casting, marketplace,
worktree creation, issue pickup, PRD implementation, Git publication, dispatch,
cloud change or merge is enabled. CAO owns lifecycle transitions and safe outputs.

## Validation boundary

`python3 modernization/squad/validate_assets.py` checks the actual roster,
charter paths, provenance hashes, casting pair, enabled local reference closure,
local-mode config and excluded/stale assets. This is static asset evidence only:
it does not prove a real gh-aw run, model behavior, deployment, independent
review results, publication, concurrency isolation or policy enforcement.
Parent integration owns workflow tests and compilation.
